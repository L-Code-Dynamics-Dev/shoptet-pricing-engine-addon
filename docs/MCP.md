# MCP agent interface — initial read/plan implementation

HTTP endpoint: `POST /mcp` (JSON-RPC 2.0, Streamable HTTP-compatible JSON response). Protocol version advertised: `2025-03-26`. This is an initial stateless subset, not a full interoperability certification.

## Authorization

A dedicated opaque bearer credential is generated by a trusted operator with a CSPRNG (at least 32 random bytes, encoded as URL-safe base64). Store only its SHA-256 hex digest in `mcp_credentials`, scoped to an existing active installation. Assign least-privilege scopes: `installation:read`, `pricing:preview`. Expiration and revocation are enforced on every request. No API to issue credentials exists until authenticated installation/admin workflows are completed. Never reuse Shoptet API credentials as MCP bearer tokens. Do not log tokens.

`Origin`-bearing requests are currently rejected, so browser MCP clients cannot connect. Native/server-to-server clients can connect. Production rollout requires HTTPS, gateway rate limiting, verified trusted-origin handling if browsers are supported, token lifecycle UI, D1 migrations and abuse monitoring.

## Available tools

- `installation_status`: requires `installation:read`; returns only the authenticated shop installation state.
- `pricing_preview`: requires `pricing:preview`; accepts integer minor-unit base/action prices, tier percent, optional product/brand/category caps and optional code+VAT; returns calculated price and Shoptet PATCH **preview**, never performs writes.

No execute tools are exposed. Tool arguments cannot select a shop or tenant. The shop is resolved from the credential and validated against active installations. MCP requests do not receive Shoptet API secrets.

## Example JSON-RPC request body

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"pricing_preview","arguments":{"baseMinor":10000,"actionMinor":8500,"tierPercent":20,"code":"SKU-1","vatRate":"21.00"}}}
```

## Deferred before production

Real Shoptet OAuth/installation, credential issuance UI, token rotation, request audit trail, explicit user approval for writes, transactional sync lock, Shoptet sandbox E2E, pricing parity tests against original OKfish, rate limiting, and external MCP client interoperability tests. The existing app remains non-deployed and live writes disabled.

## Confidentiality boundary (mandatory)

The agent-facing MCP contract returns only authorized business outcomes. It MUST NOT expose source code, internal architecture, infrastructure hostnames, database schema, internal identifiers, deployment configuration, Shoptet credentials, secrets, stack traces, policy implementation, or private runbooks. In particular, `pricing_preview` returns only the calculated price and whether a change was applied; `installation_status` returns only an active boolean. No raw PATCH payloads, shop IDs, timestamps, or internal policy caps are returned.

Do not depend on agent system prompts to protect intellectual property. Keep privileged data outside MCP responses and tool descriptions, restrict scopes by authenticated installation, sanitize errors, and review all future tools for information disclosure. An agent may describe customer-facing behavior, but must not claim access to or reveal internals. The platform cannot guarantee what a third-party agent says from independent knowledge; it can ensure these tools do not supply protected internals.

Before production: verify every MCP response and error with automated non-disclosure tests, add rate limiting and audit logging without secrets, and run prompt-injection evaluations. Any diagnostic/admin endpoints exposing internals must be isolated from customer MCP credentials.

## Frontend installation (in development)

`frontend_assets_preview` (scope `assets:preview`) validates an allowlisted manifest for five OKfish-derived frontend asset names. The agent receives only filenames, count and a confirmation that nothing was applied. No SFTP hostname, credentials, internal paths or architecture are exposed via MCP.

`packages/core/src/asset-deployment.mjs` contains a transport-independent, tenant-bound deployment executor with hash checks, approval checks, staging and cleanup. **It is not wired to a live SFTP transport or an MCP execute tool.** The `approval` object is currently an injected trusted-service contract, not a cryptographically validated customer approval. Before production: implement persisted one-time approvals, per-shop encrypted SFTP credentials, upload rollback/backups, per-shop locking, actual SFTP adapter, a safe asset distribution mechanism, Shoptet integration verification and end-to-end tests. Never use the original OKfish SFTP credentials for other shops.
